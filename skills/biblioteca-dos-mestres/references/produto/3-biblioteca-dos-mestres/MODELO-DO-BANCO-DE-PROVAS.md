# O Banco de Provas - [NOME DO SEU PRODUTO]

Copie este arquivo uma vez por produto. Preencha-o antes de escrever uma única linha de copy.
Este é o entregável #1 do CopyOS - e o motivo pelo qual este sistema não alucina:
**todo gancho, estatística, alegação e elemento de prova na sua copy de LANÇAMENTO precisa remeter a uma linha deste arquivo. Se não está aqui e não é verificável, o sistema escreve um placeholder nomeado e sinaliza, em vez de inventar. Nada é bloqueado: você decide o que vai ao ar.**

Seções vazias são PEDIDOS, não lacunas para disfarçar. O caminho mais rápido para uma copy melhor é um banco mais completo.

Uma nuance: no estado rotulado `speculative_ideation` (ideação especulativa) a máquina pode explorar alegações candidatas além deste banco - cada uma marcada `ESPECULATIVO - precisa de verificação` e registrada como dívida de verdade. Esses itens vivem na seção 7 (a fila de pesquisa) até serem verificados ou cortados; a checagem pré-lançamento sinaliza cada um deles como item a corrigir antes de lançar enquanto algum permanecer. O banco controla o que É PUBLICADO, não o que é explorado.

## Esquema de entrada (para qualquer ferramenta ou sistema de memória)

`alegação/fato | valor | nível de evidência | fonte (arquivo/URL/data) | mercado | faixa (V/A/AD/R: Verde, Amarelo, Aprovado pelo Dono, Vermelho) | status (verificado/expirado) | utilizável-como (gancho/prova/FAQ)`

**Níveis de evidência:** `verificado-atual` (checado numa fonte viva neste mês) → `snapshot-local` (exportação datada que pode ficar desatualizada) → `inferência` (raciocinado, não declarado) → `suposição` (de trabalho; deixe visível antes de confiar nela). A copy lidera com o nível mais alto disponível; uma `suposição` nunca é publicada como estatística.

**Manutenção:** quando a fonte de uma alegação passar de ~90 dias para qualquer coisa volátil (preços, contagens, notas de avaliação), marque-a como `expirado` e reverifique antes de reusar. Quando novos fatos verificados aparecerem (uma avaliação que vale a pena citar, um resultado de teste, uma mudança de especificação), adicione a linha no mesmo dia - o banco se acumula, e o CopyOS fica mais afiado a cada semana que você o alimenta.
